## الجزء الأول — المبدأ والطبقات

- سيستم 1 نظام مستقل بقاعدة بياناته. بيربط بالـ OMS وباقي الأنظمة بالـ API وعقد مكتوب بس، بلا ما يلمس قواعد بياناتهم.

- كل نظام مالك بياناته: مصدر حقيقة واحد لكل نوع بيانات.

- محوّل لكل نظام: كود سيستم 1 بيحكي مع «محوّل» بعقد ثابت. إذا نظام تاني سمّى نقاطه بشكل مختلف، بيتعدّل المحوّل بس.

- خادم وهمي لكل نظام بنفس العقد، عشان سيستم 1 يتبنى ويتجرّب قبل ما تجهز الأنظمة التانية.

- مسودات واقتراحات بس: كل شي بيطلع من سيستم 1 بيحتاج اعتماد بالنظام المستقبِل.

### المسار الكامل لمنتج واحد

1. سيستم 1 بيكتشف ويقيّم، وإنت بتعتمد «بحث معمّق».

2. سيستم 1 بيبعت فكرة أو مشروع لمساحة العمل، ومهام العيّنات لنظام المهام، وطلب تكلفة العيّنات للمالية.

3. بعد الامتثال والعلامة: سيستم 1 بيبعت بريف المحتوى لنظام الإنتاج.

4. نظام الإنتاج بينتج، وبعد موافقتك بينشر على صفحات الاختبار، وبيبعت لقطات المقاييس.

5. سيستم 1 بيحسب درجة الترند، والرابح بيصعد.

6. سيستم 1 بيقرأ ميزانية المالية، وبيبعت مسودة المنتج للـ OMS وخطة الاختبار للميديا باير.

7. إنت بتعتمد الخطة (بالموقع)، والميديا باير بيصرف ضمن السقف.

8. الـ OMS بيسجّل الطلبات والتسليم، وسيستم 1 بيقرأ النتيجة ويحكم: ناجح أو فاشل.

9. الناجح: بريف للكليبر وحزمة إطلاق كاملة. والنتيجة بتدخل بتعلّم الحمض.

## الجزء الرابع — قواعد العقد العامة

| البند | القاعدة |
|---|---|
| المسار | /api/v1/... لكل نظام، والتغيير الكاسر بيصير v2 مع فترة تداخل |
| الدخول | Authorization: Bearer توكن خاص بكل نظام، بأقل صلاحية |
| المفتاح الفريد | Idempotency-Key بكل طلب إنشاء: نفس المفتاح مرتين = نفس النتيجة بلا تكرار |
| تتبع الطلب | X-Request-Id بكل طلب، وبيرجع بالرد |
| المبالغ | نص عشري بخانتين ("20.00")، والعملة رمز ثلاثي (USD · JOD) |
| البلدان | رمز حرفين (SY · JO · EG · SA) |
| التواريخ | ISO 8601 مع المنطقة الزمنية |
| النص | UTF-8، والعربي كما هو |
| المعرّفات | نصوص؛ كل نظام بيحفظ معرّف الطرف التاني (external_ref) |
| الحدود | 5 طلبات بالثانية لكل نظام صادر، و20 للأحداث الواردة |
| الأحداث | event_id فريد · نوع الحدث · وقت حدوثه · البيانات، وبتوقيع |

### 1. التوقيع على الأحداث

- الترويسات: X-Zaki-Timestamp و X-Zaki-Signature.

- التوقيع = sha256 بمفتاح سري مشترك على (الوقت + "." + نص الطلب الخام).

- الرفض: توقيع غلط · وقت أقدم من 5 دقايق · event_id مكرر (بيرجع نجاح بلا معالجة تانية).

```
{
  "event_id": "evt_01J9ZK4Q8M",
  "type": "metrics.snapshot",
  "occurred_at": "2026-10-09T12:00:00+03:00",
  "data": {}
}
```

### 2. شكل الخطأ الموحّد

```
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "سعر العرض الأول ناقص",
    "details": [{"field": "offers[0].price", "issue": "required"}]
  },
  "request_id": "req_7Hc2"
}
```

| الحالة | الرمز | سيستم 1 بيعمل |
|---|---|---|
| 400 | BAD_REQUEST | بيوقف ويسجّل — خطأ بالطلب نفسه |
| 401 · 403 | UNAUTHORIZED · FORBIDDEN | بيوقف + تنبيه «التوكن بده مراجعة» |
| 404 | NOT_FOUND | بيوقف ويسجّل |
| 409 | IDEMPOTENCY_CONFLICT | نفس المفتاح بجسم مختلف — بيوقف + تنبيه |
| 422 | VALIDATION_FAILED · BUSINESS_RULE | بيوقف ويعرض السبب بالعربي بالشاشة |
| 429 | RATE_LIMITED | بيستنى حسب Retry-After ويعيد |
| 500 · 502 · 503 · 504 | خطأ بالخادم | إعادة محاولة |

### 3. إعادة المحاولة

- بس لـ 429 و5xx وانقطاع الاتصال.

- الفواصل: دقيقة · 5 دقايق · 30 دقيقة · ساعتين · 6 ساعات — وبعدها «ميت» + تنبيه، وزر «أعد الإرسال» بالشاشة.

- نفس المفتاح الفريد بكل محاولة، فما في تكرار حتى لو الطلب وصل أول مرة.
