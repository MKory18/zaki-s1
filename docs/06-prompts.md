## القسم الأول — طريقة الشغل مع GLM

### 1. قبل أول جلسة

- أنشئ مجلد المشروع، وجوّاه مجلد docs، وحط فيه ملفات Word الستة.

- افتح GLM على مجلد المشروع، وشغّل برومبت D0 مرة وحدة بس: بيحوّل الملفات لنصوص بيقرأها بكل جلسة.

- بعدها B00، وبعدها الترتيب بخطة البناء.

### 2. كل جلسة — نفس الخطوات

| # | الخطوة | ملاحظة |
|---|---|---|
| 1 | الصق U1 | GLM بيقرأ التقدّم وبيشغّل النظام وبيقلك الوضع |
| 2 | استنى كلمة «جاهز» | إذا قال في شي خربان، صلّحه أول بـ F1 |
| 3 | الصق برومبت المهمة | مهمة وحدة بس بكل جلسة |
| 4 | GLM بيطبع خطة عربية قصيرة | اقرأها: إذا فيها شي مش بالمهمة قلّه «التزم بالمهمة» |
| 5 | «تمام، ابدأ» |  |
| 6 | GLM بيبني ويشغّل الاختبارات | لا تقاطعه |
| 7 | تقرير عربي | شو انعمل · كيف أشغّل · كيف أجرّب · شو معلّق |
| 8 | جرّب بإيدك حسب «كيف تتأكد» بخطة البناء | إذا في مشكلة: F1 مع نص الخطأ أو صورة |
| 9 | «حدّث PROGRESS.md واحفظ نسخة» |  |
| 10 | آخر اليوم: نسخة احتياطية |  |

### 3. قواعد ذهبية

- ولا تلصق برومبتين مع بعض، وولا تطلب «كمّل كل شي».

- لا تقبل «خلصت» بلا اختبارات ناجحة وتجربة بإيدك.

- إذا GLM اقترح يغيّر شي برّا المهمة: «سجّله بـ PROGRESS.md كاقتراح، وكمّل المهمة».

- إذا علّق بنفس الخطأ مرتين: F2 (مراجعة) بجلسة جديدة.

- ولا تعطيه مفاتيح بالمحادثة: المفاتيح بملف .env إنت بتعبّيه بإيدك.

- الملفات بمجلد docs هي المرجع: إذا تعارض كلامه معها، الملفات بتغلب.

### 4. دليل الرموز

| الرمز | المعنى |
|---|---|
| U1 | بداية كل جلسة |
| D0 | تحويل ملفات Word لمجلد docs (مرة وحدة) |
| B00 – B20 | برومبتات البناء بالترتيب |
| F1 – F6 | الإصلاح والتعديل والإضافة |
| A01 – A17 · H01 – H02 | برومبتات الوكلاء الي بتشتغل جوّا النظام |
| K1 – K3 | برومبتات Kimi اليدوية لدويين والمصادر الصينية |

برومبتات البناء والوكلاء كلها بالعربي؛ مفاتيح JSON بالإنجليزي لأن الكود بيقرأها.
